04 / 10  ·  EQUATIONS
the four equations

math, not magic

commit_id = sha256(JCS(object − {commit_id, signature}))

content-addressed id over the canonicalized object, with the id and signature fields removed.

signature = Ed25519_sk(JCS(object + commit_id))

deterministic Ed25519 signature over the canonical object plus its freshly computed commit_id.

agent_id = did:alethech: + b32(sha256(JCS(pk))[:16])

identity derives from the root public key — operational keys rotate, the agent_id does not.

C ∈ ancestry(cutoff_head) ⟹ VALID_HISTORICAL

a commit is valid iff its ancestry is reachable from the last pre-rotation head.

note JCS = RFC 8785 canonical JSON. Same bytes in, same hash out — every time, on every machine.
05 / 10  ·  VERDICTS
the two verdicts

valid or not

verdict VALID_HISTORICAL C ∈ ancestry(cutoff_head)
verdict NOT_IN_PROVEN_PRE_ROTATION_HISTORY C ∉ ancestry(cutoff_head)
critical: the verifier does NOT claim to prove WHEN the commit was created — only that it is reachable from a verified head.
06 / 10  ·  KEY ROTATION
key rotation

rotate keys, keep identity

key-001 revoked
cutoff_head
key-002 active

agent_id derives from the root, not the operational key. Keys can be revoked and replaced; the identity they attest to does not move. Reachability through the cutoff_head is what carries continuity across the rotation.

07 / 10  ·  ANTI-ROLLBACK
anti-rollback

sequence is the authority

forward monotonic sequence — accepted:

10→ 11→ 12→ 13→ 14→ 15 [ ACCEPTED ]

stale sequence — rejected as rollback:

5 [ REJECTED — rollback ]

the system clock is NOT the authority — sequence is. Time lies; monotonic counters cannot be wound back without breaking the chain.
